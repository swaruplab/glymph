# Beating CellBender takes amortization, not attention

As of November 2026 the deep-learning literature on ambient RNA removal for droplet RNA-seq still consists of two variational autoencoders, CellBender and scAR; the searches behind this report found no transformer, diffusion or foundation model built for ambient decontamination, and every new RNA decontamination tool from 2023 to 2026 is non-neural. Independent benchmarks keep CellBender first or near first once endogenous retention and count integrity are scored alongside removal, while scAR removes slightly more ambient signal at the price of stripping about 45% of endogenous signal and writing counts that exceed the raw data; SoupX and DecontX are fast and safe but less sensitive. CellBender's reproducible weaknesses are under-correction of the few dominant ambient genes in dirty nuclei data, mild over-correction on clean data, fragile training defaults, a single GPU, and a per-library training loop that costs 20 to 60 GPU minutes on the authors' hardware. No method of any kind has ground-truth validation on Parse or BD Rhapsody, where the premise of one empty-droplet plateau and one ambient profile per run fails outright (Parse) or holds only per cartridge lane with truncated empties (Rhapsody). No existing tool therefore meets the brief, and this report recommends building one: a pretrained, ambient-conditioned MLP VAE with an explicit Poisson mixture of native expression plus a unit-structured background, whose integer output comes from binomial thinning of the observed counts so that output never exceeds input. A gene-token transformer backbone is not justified, because it costs about a thousand times more compute per cell with no independent evidence of better count reconstruction; attention earns a place only as a small set encoder over empty barcodes and as an ablation. A multi-GPU node should run one library per GPU and reserve distributed training for the one-off pretraining job, with targets of at least 10x (per-library fit) and 30x (amortized inference) over CellBender on the same GPU, both still to be measured. Until that model is validated, use CellBender v0.4.0 for 10x, CellBender per sublibrary with hand-tuned settings for Parse, and DecontX with a CellBender cross-check for Rhapsody, and never scAR or CellClear.

_Evidence labels used below. Cited statements without a label come from peer-reviewed papers, primary documentation or source code. **[preprint]** is not peer reviewed. **[self-reported]** comes from a tool's own authors. **[snippet]** was seen only as a search excerpt. **[unverified]** was flagged in the research notes as not confirmed. **[inference]** and **[proposal]** mark this report's own reasoning and design, which are not findings from the literature._

## Two VAEs make up the entire neural field for droplet RNA

CellBender is the reference point. It models each droplet as a negative-binomial cell term, a VAE decoder over a 64-dimensional latent gated by a Bernoulli cell-presence variable, plus a Poisson noise term with a constant ambient source and a swapping source proportional to total counts ([CellBender preprint v2](https://www.biorxiv.org/content/10.1101/791699v2.full); [model.py](https://github.com/broadinstitute/CellBender/blob/main/cellbender/remove_background/model.py)). It trains from scratch on every library with Pyro stochastic variational inference, 150 epochs at minibatch 128 with enumeration over the cell or no-cell variable, and then builds integer output in a separate step that solves a multiple-choice knapsack problem under per-gene noise budgets set by `--fpr` ([CellBender reference docs](https://cellbender.readthedocs.io/en/latest/reference/index.html); [CellBender preprint v2](https://www.biorxiv.org/content/10.1101/791699v2.full)). Since v0.2.0 the output is input minus estimated noise, so **no output entry exceeds the raw count** ([CellBender changelog](https://cellbender.readthedocs.io/en/latest/changelog/index.html)). The gene-expression algorithm has been **frozen since v0.3.0 (August 2023)**: v0.3.2 and v0.4.0 (15 August 2026, Python 3.10 to 3.12 and current PyTorch) reproduce v0.3.0 outputs, and the maintainer's open 2026 work targets memory use and multi-modal inputs, not accuracy, training speed or non-10x chemistries ([CellBender releases](https://github.com/broadinstitute/CellBender/releases); [PR 466](https://github.com/broadinstitute/CellBender/pull/466); [PR 477](https://github.com/broadinstitute/CellBender/pull/477)).

scAR from Novartis is the only other deep generative remover for droplet RNA. It was posted to bioRxiv in January 2022 and no journal version was found ([scAR preprint](https://doi.org/10.1101/2022.01.14.476312); [Novartis/scar](https://github.com/Novartis/scar)); it also ships as `scvi.external.SCAR`, the only scvi-tools model whose stated task is ambient RNA removal ([scvi-tools user guide](https://docs.scvi-tools.org/en/stable/user_guide/index.html)). Four design choices separate it from CellBender. The ambient profile is a fixed empirical input estimated from cell-free droplets, not a jointly learned parameter; there is no cell calling; the default likelihood is binomial with a `sparsity=0.9` prior on native signal; and denoised counts are drawn from the posterior predictive ([scar source](https://github.com/Novartis/scar/blob/main/scar/main/_scar.py); [SCAR API](https://docs.scvi-tools.org/en/stable/api/reference/scvi.external.SCAR.html)). The network is small (hidden layers of 150 and 100 units, latent dimension 15), the original repository was last pushed in August 2024, and the code documents no multi-GPU option ([scar source](https://github.com/Novartis/scar/blob/main/scar/main/_scar.py); [Novartis/scar](https://github.com/Novartis/scar)). **[unverified]** The body of the scAR preprint could not be opened, so its own benchmark numbers, exact likelihood equations and runtime claims are missing from this report; the facts above come from source code and documentation.

Everything else neural addresses another modality or another problem. totalVI models background only for proteins and keeps a plain negative binomial for RNA ([totalVI guide](https://docs.scvi-tools.org/en/stable/user_guide/models/totalvi.html)); scPDA is a protein-only VAE ([Zhu and Li 2025](https://doi.org/10.1186/s13059-025-03686-4)). The deep generative work of 2025 to 2026 went into spatial data: resolVI decomposes each cell into true expression, neighbor diffusion and unspecific background ([Ergen and Yosef 2026](https://doi.org/10.1038/s41592-026-03212-9)), DeSpotX adds anchor genes and a learned diffusion prior **[preprint]** ([Wang and Gentles 2026](https://doi.org/10.64898/2026.05.12.724704)), and SpaceBender reuses largely unmodified CellBender code with spatial ambient neighborhoods **[preprint]** ([Chen et al. 2026](https://doi.org/10.64898/2026.04.20.719715)). Neither preprint has an independent evaluation.

No transformer or foundation model targets ambient RNA. A full-text search for the string "ambient" returned zero occurrences in Nicheformer, scPRINT, GeneCompass and CellFM ([Nicheformer](https://europepmc.org/article/PMC/PMC12695652); [scPRINT](https://europepmc.org/article/PMC/PMC12003772); [GeneCompass](https://europepmc.org/article/PMC/PMC11615217); [CellFM](https://europepmc.org/article/PMC/PMC12092794)). What these models call denoising is depth recovery: scPRINT is trained to "recover the known transcriptomic profile from a purposefully downsampled expression profile" ([Kalfon et al. 2025](https://europepmc.org/article/PMC/PMC12003772)). That objective adds counts, and smoothing-type methods are documented to create false positives ([Andrews and Hemberg 2018](https://doi.org/10.12688/f1000research.16613.2)); decontamination must only subtract. **[inference]** A model pretrained on uncorrected public matrices with a depth-upsampling objective will reproduce ambient counts as if they were biology; no paper tests this. **[unverified]** scGPT, scFoundation and Geneformer were checked at abstract level only, and UCE, CellPLM, TranscriptFormer, STATE and scMulan were not checked at all.

The non-neural toolbox is larger and supplies both the baselines and several ideas worth importing. Two 2026 preprints matter most: CellSweep, an EM multinomial mixture from the Pachter lab with separate ambient and "bulk" contamination terms, and AmbiDose, which enforces integer output that never inflates counts.

## Benchmarks keep CellBender on top and map its three failure modes

### Removal alone ranks scAR first; removal plus retention ranks CellBender first

Four independent studies define the evidence. They agree that no tool wins everywhere, that CellBender and scAR remove the most ambient signal, and that scAR pays for it in lost and invented counts.

| Benchmark | Ground truth | CellBender result | Other tools | Authors' recommendation |
|---|---|---|---|---|
| [Janssen et al. 2023](https://doi.org/10.1186/s13059-023-02978-x), Genome Biology; CellBender v0.2.0 | Mouse kidney, three strains per 10x 3' v3.1 channel; three cell and two nuclei replicates; background 3 to 35% of UMIs per cell | Most accurate per-cell background; Slc34a1 stays detectable in 7% of non-proximal-tubule cells, against about 60% raw, and in 4% of non-proximal-tubule nuclei; fine structure slightly worse than raw at low background; about 45 CPU hours per channel | SoupX leaves 54% in cells (under 1% in nuclei) and cannot capture cell-to-cell variation; DecontX default fails on nuclei (87%), 20% with an empty-droplet background | Always correct before marker analysis; for clustering and classification only when background is high |
| [Cargnelli et al. 2026](https://doi.org/10.3389/fbinf.2026.1844838), Frontiers in Bioinformatics; v0.3.2 | 64 samples: species mixing, strain mixing, Smart-seq2 negative control, synthetic | Ranked first overall; ambient removal score 0.604; more prone to over-correction on clean data than reduced-mode SoupX; highest compute demand | scAR removal score 0.679 but removes 0.445 of endogenous signal; DecontX full mode a close second; scCDC and FastCAR show no positive effect on interpretation | CellBender or DecontX (full) for contaminated data; SoupX (reduced) otherwise |
| [Schroeder et al. 2026](https://www.biorxiv.org/content/10.64898/2026.04.08.717130v1.full), bioRxiv **[preprint]**; v0.3.0 | Five 10x human-mouse mixtures; PBMC; prefrontal cortex snRNA-seq (158,490 nuclei); one BD Rhapsody dataset | Sensitivity 94.0 ± 2.7%, extrapolated specificity 100%, same-species removal ratio near 1.0 | scAR 95.6% but removes 18 to 72% of counts and adds 17 to 60% artificial counts; SoupX 70.9%; DecontX 53.2%; scCDC 22.3% | CellBender with a GPU; SoupX as lightweight option; DecontX for non-droplet data; exclude scAR and CellClear |
| [Nie et al. 2026](https://doi.org/10.1038/s41467-026-77458-4), Nature Communications; v0.3.0 | Pooled-donor PBMC with mtDNA genotype truth; simulations; marker truth in several tissues | Closest absolute contamination estimate with FastCAR (mean RMSLE below 0.06); lowers kNN overlap with genotype-cleaned data | DecontX top composite accuracy; scAR "most robust" but overestimates contamination; CellClear best at subtype level | SoupX to estimate, then CellClear or CellBender to correct |

The disagreement about the winner is methodological. Nie's "decontamination efficacy" rewards any drop of marker signal in off-target cells and does not penalize invented or lost endogenous counts, whereas Cargnelli and Schroeder score retention and count integrity **[inference]**. The integrity evidence is concrete: scAR pushed MS4A1 detection in B cells from about 82% to 99% and reassigned about 17% of cells ([Nie et al. 2026](https://doi.org/10.1038/s41467-026-77458-4)), and in prefrontal cortex snRNA-seq it **created 8 novel fine cell types (4,343 nuclei) while 141 macrophages disappeared** ([Schroeder et al. 2026](https://www.biorxiv.org/content/10.64898/2026.04.08.717130v1.full)). "Beating CellBender" therefore means beating it on fidelity and speed at once; winning on removal alone only reproduces scAR. Three flags apply. The benchmarks ran CellBender 0.2.0, 0.3.0 and 0.3.2, so none tested the current release directly, although v0.4.0 is documented to match v0.3.0 output. The abstract of Nie et al. and its GEO record summarize the ranking differently, probably from different drafts **[unverified]**. And Cargnelli et al. state that CellBender and scAR "tend to introduce new counts for lowly expressed genes", which contradicts CellBender's subtraction-only design; the notes could not resolve this and suspect a normalization artifact **[unverified]**.

### CellBender's error profile is asymmetric

On species mixtures CellBender is close to ideal. Its failures appear at the two ends of the contamination range and in operations. First, it **under-corrects the handful of genes that dominate the ambient pool** in highly contaminated data: milk-protein genes in mammary nuclei and hormone genes in pancreas stay under-corrected ([Wang et al. 2024](https://doi.org/10.1186/s13059-024-03284-w), a competitor's benchmark), 8 of 9 hemoglobin genes remain differentially expressed in fetal-liver pro-B cells ([Arora et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12459771/)), and users of v0.3 report that mitochondrial genes are not removed from nuclei data ([issue 310](https://github.com/broadinstitute/CellBender/issues/310)). The maintainer confirms that v0.3 is deliberately "more conservative" after v0.2 over-removed noisy genes at high FPR ([issue 277](https://github.com/broadinstitute/CellBender/issues/277)). Second, it shows mild over-correction where there is little to remove: lower kNN agreement with genotype-cleaned data at low background ([Janssen et al. 2023](https://doi.org/10.1186/s13059-023-02978-x); [Nie et al. 2026](https://doi.org/10.1038/s41467-026-77458-4)) and more over-correction on no-ambient controls than reduced-mode SoupX ([Cargnelli et al. 2026](https://doi.org/10.3389/fbinf.2026.1844838)). Third, training is fragile at the defaults. The docs tell users to "re-run with half the learning rate" when the learning curve spikes or dips ([troubleshooting docs](https://cellbender.readthedocs.io/en/latest/troubleshooting/index.html)); one user needed at least one halving for about half of a frozen-nerve snRNA-seq cohort, with called cells swinging from about 17,500 to 30,500 for one sample ([issue 276](https://github.com/broadinstitute/CellBender/issues/276); the specific rates in that thread are **[unverified]**), and the maintainer concedes that "CellBender seems to struggle to call cells on some experiments" ([issue 163](https://github.com/broadinstitute/CellBender/issues/163)). The post-training estimator adds its own failures: multi-day hangs above about 25,000 cells with `--estimator-multiple-cpu` ([issue 362](https://github.com/broadinstitute/CellBender/issues/362)), out-of-memory kills with one user needing more than 320 GB of RAM ([issue 295](https://github.com/broadinstitute/CellBender/issues/295)), the withdrawn v0.3.1 whose integer overflow produced negative counts ([issue 306](https://github.com/broadinstitute/CellBender/issues/306)), and an open, unconfirmed report of wrong noise-count decoding that would affect the default estimator's targets **[unverified]** ([issue 460](https://github.com/broadinstitute/CellBender/issues/460)).

### Per-cell contamination estimates are weak for every tool

Against mtDNA genotype truth, the best cell-to-cell rank agreement of any tool is reported only as a Kendall tau above 0.065 and an R2 above 0.012 ([Nie et al. 2026](https://doi.org/10.1038/s41467-026-77458-4)). In genotype-aware simulations CellBender v0.2.2 had a 19.0% mean absolute error in per-droplet ambient fraction and no correlation with truth **[self-reported, preprint]** ([Alvarez et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12407767/)), and in a 7-donor pool CellBender and SoupX agreed on the ambient profile but not on per-cell estimates **[self-reported; the reported negative sign on an r2 value is unverified]** ([Schaefer et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC11957168/)). Calibrated per-cell contamination is an open endpoint on which a new method can stand out **[inference]**.

### Two 2026 preprints claim CellBender-beating accuracy in seconds, without a network

CellSweep reports removing 98.84% and 98.59% of cross-species counts on a 10x human-mouse mixture against 94.52% and 97.29% for CellBender, while retaining about 98% of true counts, in **about 25 seconds on 16 CPU threads**; its authors also ran it on Parse/SPLiT-seq data **[self-reported, preprint]** ([Caskey et al. 2026](https://www.biorxiv.org/content/10.64898/2026.03.04.709349v1.full)). The same authors list its limits: it needs cell-type labels, "the multinomial assumption ignores overdispersion", and the likelihood is "nearly flat along directions that trade cell-type expression against ambient contamination", so the starting ambient fraction selects among near-equal solutions. AmbiDose reports 92.0% cross-species removal at 99.6% same-species retention on a held-out GEM-X mixture **[self-reported, preprint, abstract only]** ([Li et al. 2026](https://doi.org/10.64898/2026.09.27.754849)). A search snippet from that preprint puts CellBender's median per-cell cross-species removal at 0.208 on the same data, which conflicts with the 94% aggregate sensitivity in Schroeder et al.; metric, chemistry and settings differences are all plausible, and neither number should enter a claim before it is reproduced **[snippet, unverified]**. These two tools set the speed bar. A deep model that only matches CellBender's accuracy at tens of seconds per library has not obviously beaten a non-neural EM fit.

### Brain nuclei combine high background with no ground truth

Single-nucleus data carry more ambient RNA than single-cell data: an average load of **11.80% versus 7.79%** across 49 truth-labelled samples ([Cargnelli et al. 2026](https://doi.org/10.3389/fbinf.2026.1844838)), and 17% and 35% medians in nuclei from frozen kidney against 3% and 11% in the matched cells ([Janssen et al. 2023](https://doi.org/10.1186/s13059-023-02978-x)). The absolute number of contaminating UMIs per barcode is roughly constant within a library ([Janssen et al. 2023](https://doi.org/10.1186/s13059-023-02978-x)), so low-UMI nuclei such as glia carry the highest fractions **[inference]**. In brain, ambient RNA is predominantly neuronal and splits into a non-nuclear part with a low intronic read ratio and a nuclear part; more than 75% of mouse oligodendrocyte nuclei carried reads from Rbfox1, Snap25 and Syt1 despite almost no overlap by smFISH, and 46 of 58 published "immature oligodendrocyte" markers were ambient markers ([Caglayan et al. 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9789184/)). In that study CellBender was "consistently better" than SoupX and DecontX in glia, yet residual signal persisted in a glial subcluster and **no tool reduced contamination inside neurons**. In prefrontal cortex snRNA-seq CellBender raised CellTypist confidence by 0.163 from a 0.758 baseline, about twice DecontX's gain ([Schroeder et al. 2026](https://www.biorxiv.org/content/10.64898/2026.04.08.717130v1.full)). SoupX estimates for mouse cortex nuclei range from 0.07 to above 0.25 depending on the isolation method ([Kersey et al. 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13030979/)). The notes found **no genotype- or species-based measurement of ambient fraction in brain nuclei** and no peer-reviewed benchmark with per-count truth in brain; which tool the large brain consortia pipelines use was also not confirmed beyond ASAP CRN, which runs CellBender v0.3.0 at defaults ([ASAP CRN QC](https://brain-map.org/bkp/explore/abc-atlas/asap-crn-cloud-pmdbs-qc)).

## Parse and Rhapsody have no validated remover and a differently structured background

### CellBender's premise is a 10x premise

The CellBender docs tie the method to the "ambient plateau" of the UMI rank curve and say that with "no discernible plateau" the tool "may struggle" ([usage docs](https://cellbender.readthedocs.io/en/latest/usage/index.html)). The maintainer is direct about split-pool data: the noise model "was created with droplet-based experiments in mind" and "in SPLiT-seq, the concept of empty droplets is gone" ([issue 226](https://github.com/broadinstitute/CellBender/issues/226)). The code will ingest nearly any count matrix, including BD Rhapsody CSV output ([io.py](https://github.com/broadinstitute/CellBender/blob/main/cellbender/remove_background/data/io.py)), but user questions about Rhapsody's newer output (2024), Parse output (February 2026) and a bead-based platform with 7 to 9 times too many called cells (November 2026) have no maintainer reply ([issue 359](https://github.com/broadinstitute/CellBender/issues/359); [issue 441](https://github.com/broadinstitute/CellBender/issues/441); [issue 480](https://github.com/broadinstitute/CellBender/issues/480)). The notes found **no publication that tests CellBender against species or genotype truth on any non-10x chemistry**; the only non-10x dataset in the CellBender paper is a PIPseq PBMC sample in the supplement ([Fleming et al. 2023](https://www.nature.com/articles/s41592-023-01943-7)).

### Parse fills its whole barcode space with background

Parse states that a free RNA would have to follow one cell through every barcoding round, a 1 in 3,538,944 event **[vendor claim, snippet only]** ([Parse support](https://support.parsebiosciences.com/hc/en-us/articles/360052760772-Will-I-pickup-ambient-RNA-in-my-data)). A 2026 reanalysis of seven matched 10x and Parse experiments contradicts the conclusion drawn from it **[preprint]** ([Caskey and Hallgrimsdottir 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13692299/)). **More than 99.9% of valid barcode combinations received reads in four of seven Parse experiments**; every cell barcode in human-mouse mixtures carried cross-species counts, with medians of 1.2% and 2.1% in Evercode v1 against interquartile ranges of 0.5 to 0.8% and 1 to 2% for Chromium v3.1; knees were less pronounced than in 10x; and the mechanism "remains uncharacterized". Those authors declined to run SoupX or CellBender because the estimators "have not been validated on split-pool data". Peer-reviewed evidence adds a spatial structure: in the IGVF 8-cube study, loading different tissues on one barcoding plate produced detectable contamination between neighboring wells ([Rebboah et al. 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13069871/)). Other estimates point the other way: SoupX puts Parse Evercode v3 under 5% like most kits ([Elz et al. 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC12770963/)), and one 2026 preprint, probably King et al., reportedly finds slightly more ambient signal in 10x **[snippet only]** ([bioRxiv](https://www.biorxiv.org/content/10.64898/2026.04.20.719117v1.full)). The ranking of platforms by ambient level is unresolved because no estimator has been validated on split-pool data.

Practice on Parse data is CellBender with manual overrides. The Mortazavi lab IGVF pipeline at UC Irvine runs CellBender per sublibrary on the unfiltered kallisto matrix with about 67,000 expected cells for 1M kits and 13,000 for 100k kits, total droplets about three times that, and half the default learning rate ([parse_pipeline README](https://github.com/mortazavilab/parse_pipeline)); the published study tuned parameters per sublibrary by hand and reports that CellBender substantially reduced apparent cross-tissue contamination ([Rebboah et al. 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13069871/)). These settings exceed the 70,000-droplet cap on CellBender's automatic choice ([consts.py](https://github.com/broadinstitute/CellBender/blob/main/cellbender/remove_background/consts.py)), so they have to be set by hand **[inference]**. The one paper that tried SoupX on Parse data saw no improvement ([Filippov et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11552371)).

### Rhapsody has real empty wells, but truncated and unlabelled

BD's documentation names ambient RNA, diffusion to neighboring wells after lysis, cells in bead-less wells and bead-synthesis contamination as noise sources, yet the pipeline through v4.0 (September 2026) only calls putative cells and contains no ambient correction of expression counts ([BD putative cells](https://bd-rhapsody-bioinfo-docs.genomics.bd.com/steps/steps_putative_cells.html); [BD release notes](https://bd-rhapsody-bioinfo-docs.genomics.bd.com/release_notes.html)). A standard output, `_RSEC_MolsPerCell_Unfiltered_MEX.zip`, holds **every cell index with at least 10 reads** and no putative or noise flag ([BD outputs](https://bd-rhapsody-bioinfo-docs.genomics.bd.com/outputs/top_outputs.html); [BD data tables](https://bd-rhapsody-bioinfo-docs.genomics.bd.com/outputs/outputs_datatables.html)). In the one head-to-head with an ambient analysis, which used scAR's noise ratio, Rhapsody carried more ambient noise per cell than 10x in fresh tumors, the noise was uniform across cell types where 10x noise was dominated by neutrophil transcripts, and about 5% of called cells on both platforms were indistinguishable from the ambient profile ([Colino-Sanguino et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11408078)). The only tool benchmark with a Rhapsody dataset ran CellBender on the unfiltered matrix with 120,000 expected cells and 132,000 total droplets, saw scAR generate three spurious cell types and CellClear fail, recommends DecontX for non-droplet data, and calls the suitability of droplet-validated tools for plate data "an open question" **[preprint]** ([Schroeder et al. 2026](https://www.biorxiv.org/content/10.64898/2026.04.08.717130v1.full)). That dataset has marker-based evaluation only; no species-mixing or genotype-mixing ambient truth was found for Rhapsody.

### The chemistry dictates which units share a background

The table maps CellBender's assumptions onto the three platforms. The 10x column is cited; **the Parse and Rhapsody columns are inference** from the cited mechanics, and no dataset has yet estimated the relative weight of each background component on either platform.

| CellBender assumption | 10x droplets | Parse Evercode **[inference]** | BD Rhapsody **[inference]** |
|---|---|---|---|
| Empty partitions form a UMI plateau | Yes; required ([usage docs](https://cellbender.readthedocs.io/en/latest/usage/index.html)) | No partitions; non-cell barcodes are phantom combinations, debris and errors; saturated barcode space, weak knee | Physically yes (bead in a cell-free well), but the table is truncated at 10 reads |
| One ambient profile per run | Assumed; debris such as mitochondria stuck to nuclei is not modelled ([issue 163](https://github.com/broadinstitute/CellBender/issues/163)) | No; in-well background is specific to the round 1 well, which encodes the sample; chimeras are per sublibrary; neighbor wells leak | One per cartridge lane, an unresolvable mixture of all Sample-Tagged samples, plus local diffusion |

Two consequences follow **[inference]**. Parse offers information 10x never does, because a per-sample background profile is directly estimable from low-count barcodes grouped by round 1 well, and cross-sample signal in a Parse cell barcode is a clean contamination readout since collisions stay within a well. Rhapsody offers the opposite: one soup per lane contaminates all multiplexed samples and cannot be split per sample from expression data. Standard QC covariates are also platform-confounded: mitochondrial fraction runs about twofold higher on Rhapsody than on 10x ([Colino-Sanguino et al. 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC11408078)), and Parse libraries are nuclear-leaning with ribosomal fractions near zero ([Caskey and Hallgrimsdottir 2026](https://pmc.ncbi.nlm.nih.gov/articles/PMC13692299/)), so a cross-platform model that uses these as contamination proxies will learn platform identity.

## More GPUs do not fix a 150-epoch training loop

CellBender's cost is structural. The authors quote "around 20 min to 1 hour" for a typical 10x library of 5,000 to 30,000 cells on a Tesla T4 or K80 ([CellBender preprint v2](https://www.biorxiv.org/content/10.1101/791699v2.full)); an independent benchmark measured about 45 CPU hours per channel without a GPU ([Janssen et al. 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10278251/)). The docs state that "CellBender uses only one GPU, so extra GPUs won't help" ([troubleshooting docs](https://cellbender.readthedocs.io/en/latest/troubleshooting/index.html)), the maintainer's advice for a 4-GPU machine is to "run one separate cellbender run on one sample for each GPU" ([issue 109](https://github.com/broadinstitute/CellBender/issues/109)), and the code contains no mixed precision ([run.py](https://github.com/broadinstitute/CellBender/blob/main/cellbender/remove_background/run.py)). The defaults imply roughly 26,000 to 33,000 optimizer steps per library, which works out to about 1,000 to 3,500 droplet-passes per second, an order of magnitude below what scVI-class models reach at similar batch sizes **[inference from published timings; CellBender models more genes, which explains part of the gap]**. No published profile shows how CellBender's time divides between training, posterior sampling and the knapsack step, and **no CellBender timing on V100, A30, A100, RTX6000 or L40S hardware was found**; the 100 GPU hours reported for about 172,000 nuclei came from a 4 GB consumer GPU and multi-sample data ([Schroeder et al. 2026](https://www.biorxiv.org/content/10.64898/2026.04.08.717130v1.full)).

Distributed training of the existing models is not the fix. scvi-tools added multi-GPU training in v1.3.0 as Lightning DDP for a fixed list of models that does not include SCAR, each DDP rank loads the full AnnData, and the only official timing shows 62.12 s on one GPU against 40.88 s on two for 18,641 cells, a 1.5x gain ([scvi-tools multi-GPU guide](https://docs.scvi-tools.org/en/stable/user_guide/use_case/multi_gpu_training.html); [multi-GPU tutorial](https://docs.scvi-tools.org/en/1.3.3/tutorials/notebooks/use_cases/multiGPU.html)). The guide itself says that for small datasets the overhead outweighs the benefit. Pyro's multi-GPU support is limited to example-level recipes ([Pyro Lightning example](https://pyro.ai/examples/svi_lightning.html)). For VAE-sized models the binding constraints are batch size and data loading: default scVI batches are "often way too small to fully utilize a modern GPU", and a chunked zarr loader reaches 35,000 to 54,000 samples per second ([annbatch paper](https://arxiv.org/abs/2604.01949)). A single library fits on one GPU, so distributed training only pays when one shared model is trained across many libraries **[inference]**.

Transformers move in the wrong direction on cost without evidence of a gain in quality. One 2026 preprint reports inference at 14.2 cells per second for Geneformer, 12.9 for scFoundation and 1.8 for scGPT on an RTX 2080 Ti **[snippet; single source whose own method wins]** ([arXiv 2607.14163](https://arxiv.org/pdf/2607.14163)), against roughly 13,000 to 30,000 cell-passes per second derived for scVI **[inference]**; a simple operation count gives the same ratio of about 1,000 **[inference]**. Peer-reviewed evaluations report zero-shot Geneformer and scGPT underperforming simpler methods and five foundation models failing to beat deliberately simple baselines on perturbation prediction **[snippets]** ([Kedzierska et al. 2025](https://link.springer.com/article/10.1186/s13059-025-03574-x); [Nature Methods 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC12328236/)). No independent head-to-head of count-level denoising between foundation models and scVI-class models was found. The gap the literature leaves open is different: the notes found **no ambient remover that is pretrained across libraries and applied to a new library with little or no training**, although that absence comes from limited searching.

## Recommendation: build an ambient-conditioned mixture VAE that only thins observed counts

Everything in this section is the report's own design proposal or inference unless a citation is attached. No existing tool meets the brief of faster and better than CellBender across 10x, Parse and Rhapsody. CellBender cannot be faster than itself and is unvalidated off 10x; scAR fails count integrity; CellSweep comes closest on speed and claimed accuracy, but rests on self-reported preprint results, needs cell-type labels and ignores overdispersion. The proposal below takes CellBender's noise phenomenology, scAR's empirical ambient profile, CellSweep's and AmbiDose's cheap bounded output, and adds the one thing none of them has, amortization across libraries.

### Generative formulation: a Poisson mixture with a unit-structured background

**[proposal]** For barcode *n* and gene *g*, with background unit *u(n)* and amplification pool *p(n)*:

```
x[n,g] ~ Poisson( y[n]*c[n]*chi[n,g]  +  e[n]*a[u(n),g]  +  s[p(n)]*N[n]*chibar[p(n),g] )

background share   pi[n,g] = ( e[n]*a[u(n),g] + s[p(n)]*N[n]*chibar[p(n),g] ) / total rate
removed counts     m[n,g] | x[n,g] ~ Binomial( x[n,g], pi[n,g] )
output             native[n,g] = x[n,g] - m[n,g],   so 0 <= native[n,g] <= x[n,g]
```

Here *y* is cell presence, *c* the capture-scaled cell size, *chi* the decoder's native profile on the gene simplex, *a* the soup profile of the unit, *e* the ambient amount, *chibar* the pool-average cell profile, *s* the swapping fraction and *N* the barcode's total count. This keeps CellBender's structure of one constant noise source plus one proportional to total counts ([issue 226](https://github.com/broadinstitute/CellBender/issues/226)) and changes four things. The soup profile is computed in closed form as the normalized sum over surely-background barcodes of each unit, optionally refined by an EM step, and is fed to the network as an input; scAR already treats the profile as an empirical estimate ([scAR docs](https://scar-tutorials.readthedocs.io/en/main/Introduction.html)). The profiles are indexed by unit and pool, not by run. The cell-presence variable is predicted by an encoder head trained with weak labels (vendor cell calls and an EmptyDrops-style test against the unit profile), which removes both enumeration and CellBender's hard-coded UMI-crossover supervision ([model.py](https://github.com/broadinstitute/CellBender/blob/main/cellbender/remove_background/model.py)). And the likelihood is Poisson, with a gamma-Poisson rate during training to absorb overdispersion, so the background share of each observed count has an exact binomial posterior. The ambient amount *e* is anchored on each unit's low-count barcodes, consistent with the finding that contaminating UMIs per cell are roughly constant and similar to empty-droplet totals ([Janssen et al. 2023](https://doi.org/10.1186/s13059-023-02978-x)), and is allowed to depend on cell covariates for fixed-cell chemistries.

Three additions target the documented failure modes. A gene-specific heavy-tailed residual on the soup term addresses the "super-contaminating" genes that global models under-correct ([Wang et al. 2024](https://doi.org/10.1186/s13059-024-03284-w)). A learned prior that protects low-expression native genes addresses the over-removal that sinks scAR, an idea DeSpotX uses in spatial data **[preprint]** ([Wang and Gentles 2026](https://doi.org/10.64898/2026.05.12.724704)). For brain nuclei, an optional second input layer of spliced and unspliced counts lets the model learn separate profiles for the non-nuclear and nuclear ambient pools that Caglayan et al. describe; no existing remover uses this signal, and it is the extension most specific to this lab's data. Pretraining maximizes the mixture ELBO across many libraries, adds supervised terms on species-mixed and genotype-mixed libraries where part of the truth is known, and uses in-silico spiking of real empty-barcode profiles into clean profiles. A 90/10 count split provides early stopping, with the caveat that thinning validates the total rate and not the native-versus-ambient split, since ambient counts sit in both folds; negative binomial data also break plain Poisson splitting **[snippet]** ([Neufeld et al. 2023](https://arxiv.org/abs/2307.12985)).

### Architecture verdict: an MLP VAE, with attention only over a set of empty barcodes

**[proposal]** The backbone should be a two-layer MLP encoder and decoder over all genes (width 512 to 1,024), conditioned on observed depth, on categorical chemistry covariates, and on a library embedding computed from the log soup profile through feature-wise scale and shift (FiLM; cited from memory in the notes, not re-fetched). A small set encoder that pools a few thousand sampled background barcodes, by mean or by one attention block in the manner of the prompt cells in Stack and the cell sets in State **[snippets]** ([Arc Stack](https://arcinstitute.org/news/foundation-model-stack); [Arc State](https://arcinstitute.org/news/virtual-cell-model-state)), captures what the mean profile misses, such as heterogeneity of the empties and their depth distribution. That is the only place attention is recommended, and it runs once per library, not once per cell.

The honest verdict on a gene-token transformer backbone is that **the evidence does not justify it**. It costs about three orders of magnitude more compute per cell, which by itself erases the speed goal. No independent benchmark shows transformers reconstructing counts better than VAEs, and several show foundation models losing to simple baselines on other tasks. Rank encodings and value binning discard exact counts and cannot produce an integer-preserving decomposition. And the identifiability of the native-versus-ambient split comes from the empties and the mixture structure, not from encoder capacity, as CellSweep's flat-likelihood admission shows. A transformer is worth exactly one experiment: a small nonzero-gene transformer encoder swapped into the same likelihood and scored on the same truth datasets. Adopt it only if it wins clearly on removal at matched retention, because it starts 100 to 1,000 times behind on cost.

### Platform handling: units, not platforms, define the background

**[proposal]** The model never asks which vendor made the library; it asks which barcodes share a soup and which share an amplification pool. For 10x both are the library. For Parse the soup unit is the round 1 well or sample and the pool is the sublibrary, with an optional neighbor-well leakage profile. For Rhapsody both are the cartridge lane, with local diffusion absorbed as extra per-barcode dispersion because well coordinates are not recorded. Evidence of emptiness is an input and not a requirement: the model accepts an unfiltered matrix with arbitrary truncation (Rhapsody's 10-read floor), barcode metadata giving unit membership, and vendor cell calls as weak labels, and it falls back to a DecontX-like cell-only mode when no background barcodes exist. Parse needs a count-mixture definition of background per sublibrary and well because there is no plateau. Chemistry enters as an explicit covariate, and mitochondrial or ribosomal fractions are never used as fixed contamination proxies. **[unverified]** Readers must be built against real output: the split-pipe directory tree and metadata columns in the notes are partly from memory, Parse barcode whitelist sizes per kit were not verified, and whether Rhapsody's 10-read cutoff is configurable is unknown.

### Integer counts: binomial thinning, bounded by the raw matrix

**[proposal]** Output is produced by removing a binomially distributed number of the observed counts in each nonzero entry, using a budgeted rounding by default: remove the floor of the expected background total per barcode, assigned to the entries with the largest expected background counts. This is one vectorized GPU operation on nonzero entries, needs no Monte Carlo over latents, no posterior-regularization search and no knapsack solver, and satisfies 0 <= native <= raw by construction, the property that Schroeder et al. argue "must be a primary criterion" **[preprint]** ([Schroeder et al. 2026](https://www.biorxiv.org/content/10.64898/2026.04.08.717130v1.full)). A CellBender-like FPR knob survives as a single scalar multiplier on the background share, chosen from summary statistics. Two cautions carry over from the notes. Applying the Poisson split under an overdispersed training likelihood is a plug-in approximation whose accuracy on high-ambient genes is an empirical question for the species-mixing data. And no source was found that uses this split as the output stage of a neural remover, so novelty is unconfirmed, not established.

### Multi-GPU: one library per GPU, distributed training only for pretraining

**[proposal]** There are two parallelism problems and they need different answers. Per-library inference or fitting is embarrassingly parallel: hold the whole library as sparse CSR on one GPU, gather and densify batches on the device, and run one library per GPU through a Slurm array or four workers per 4-GPU node. This scales linearly with no communication, tolerates any mix of V100, A30, A100, RTX6000 and L40S nodes, and is the pattern that matters for a cohort. Distributed data-parallel training is reserved for pretraining the shared model, on a single homogeneous node (4x L40S or 4x A30) because DDP runs at the pace of the slowest rank, with batches of 4,000 to 16,000 barcodes, scaled learning rate, and the training set converted once to a preshuffled sharded zarr store on node-local scratch. Loader throughput, not GPU arithmetic, bounds that job; at the published 35,000 to 54,000 samples per second a corpus of a few hundred libraries makes pretraining an overnight run on one node **[inference, not measured]**. Write the model in plain PyTorch, not Pyro, to keep `torch.compile`, autocast and DDP straightforward; scvi-tools removed JAX support in v1.5.0 ([scvi-tools changelog](https://raw.githubusercontent.com/scverse/scvi-tools/main/CHANGELOG.md)) and no official multi-GPU recipe for NumPyro was found, so the JAX route is not worth pursuing. **[unverified]** Mixed-precision choices (bf16 on A30, A100 and L40S; fp16 with gradient scaling on V100) come from memory in the notes, and the generation of the cluster's RTX6000 cards and the V100 memory size were not checked.

### Speed targets: 10x for per-library fitting, 30x for amortized inference

The cited baseline is 20 to 60 minutes per 10x library on a T4 or K80, which puts a 100-library cohort at 33 to 100 GPU hours, or about 8 to 25 hours of wall-clock on a 4-GPU node running four libraries at once **[inference from the cited figure]**. The targets are estimates to be measured, not results. A per-library fit of the mixture model at large batch size, with no pretraining, should finish in **1 to 3 minutes end to end per GPU**, at least 10x faster than CellBender on the same GPU. Amortized inference with the pretrained model is one forward pass plus the binomial split and should take **20 to 60 seconds per library**, dominated by reading and writing HDF5, at least 30x faster. A 100-library cohort on one 4-GPU node then takes about 25 to 75 minutes with per-library fitting or 10 to 25 minutes amortized, at which point CPU-side file I/O is the bottleneck and each GPU needs two to four reader processes. Parse 1M-kit sublibraries carry about 200,000 analysed barcodes and scale these budgets roughly threefold. Two honest qualifiers: CellBender on modern GPUs is faster than its T4 figure by an unmeasured factor, so the speedup must be benchmarked locally on three to five representative libraries per GPU type before it is claimed; and CellSweep's claimed 25 seconds on 16 CPU threads means speed alone is not a differentiator against the newest non-neural tools.

### Validation plan: what it takes to claim the model beats CellBender

**[proposal]** The primary endpoint is two-dimensional, the fraction of truth-labelled ambient counts removed against the fraction of truth-labelled endogenous counts retained, reported per dataset with count integrity alongside; this is how the two most critical 2026 benchmarks rank tools. Because CellBender has an FPR knob, compare removal-retention curves across settings and not single operating points. Clustering metrics serve only as non-inferiority checks, since at most 1.3% of cells change label after correction ([Janssen et al. 2023](https://doi.org/10.1186/s13059-023-02978-x)).

The plan needs two things the public record lacks. One is a pooled multi-donor or human-plus-mouse cortex nuclei experiment with genotype or species truth, run on 10x, Parse and Rhapsody from the same nuclei preparation; it would fill the two bolded gaps at once and would be a citable resource independent of the model. The other is a fixed baseline panel: CellBender v0.4.0 at defaults and at several FPR values, SoupX, DecontX with and without an empty-barcode background, CellSweep, AmbiDose, and scAR as the known over-corrector. A defensible claim then reads: higher removal at non-inferior retention on every truth dataset, zero entries above raw, no worse than CellBender on negative controls, better per-cell calibration with confidence intervals, no spurious or vanished cell types, and wall time, peak RAM and GPU memory at 10,000, 50,000 and 150,000 cells on named hardware. Report variance across random seeds as well; CellBender fixes its seed at 1234, so its seed-to-seed variance has never been measured ([consts.py](https://github.com/broadinstitute/CellBender/blob/main/cellbender/remove_background/consts.py)). Run doublet detection in both orders, because detectors perform best before ambient correction for every corrector except CellBender **[preprint]** ([Meier et al. 2026](https://doi.org/10.64898/2026.10.13.758369)).

### Main risks

The largest scientific risk is identifiability. The likelihood is nearly flat along directions that trade native expression against ambient contamination, as the CellSweep authors state for their own model, and a pretrained native-expression prior can lean toward the marker patterns of its training tissues; thinning-only output caps the damage at removing true counts, never inventing them, but held-out tissues and chemistries are required to detect the bias. The second risk is that pretraining has no clean labels: public corpora contain ambient RNA, so supervision rests on a small set of mixture datasets, simulation, and spiking, and simulations are known to miss gene-gene covariance ([Cargnelli et al. 2026](https://doi.org/10.3389/fbinf.2026.1844838)). The third is competitive: if independent testing confirms CellSweep's or AmbiDose's self-reported numbers, a non-neural tool already delivers most of the benefit and the deep model must justify itself on label-free operation, per-cell calibration, overdispersion and platform structure. The fourth is the output stage, since the Poisson plug-in split can under-correct exactly the dominant ambient genes where CellBender already fails. The fifth is validation supply: Rhapsody and brain nuclei have no count-level truth today, the Parse background mechanism is uncharacterized, and the unit-structured background model is a reasoned mapping with no data behind its component weights. The sixth is the speed claim itself, which rests on derived throughputs, guessed I/O times and untested code sketches. Finally, cell calling without a plateau on Parse is its own research problem, and a remover that calls cells badly fails regardless of how well it thins counts.

### Unverified items that could change this recommendation

Several flags from the notes bear directly on decisions. The scAR preprint body, the AmbiDose full text and the numeric runtime and memory tables of the Cargnelli and Nie benchmarks were not readable, so scAR's own claims and all benchmark resource figures are missing. The transformer throughput figures come from one preprint with a competing method, and the foundation-model benchmark conclusions are snippet-level. Whether Cell Ranger 9 or 10 added count-level ambient correction could not be checked because 10x pages were rate-limited; no evidence suggests it has. The CellBender version in the Mortazavi lab pipeline is written as "3.2.0" and is probably v0.3.2. The explanation for scAR writing values above raw counts (resampling the whole profile, not thinning observed entries) is a recollection of its implementation, not a verified reading. DecontX's effect on local structure conflicts between Janssen (distortion) and Nie (preserved). And the statement that no pretrained cross-library ambient model, no intron-aware remover and no split-pool or microwell-specific method exists reflects limited searches, not proof of absence.

## Conclusion

The opening for a better tool is narrower and more concrete than "a modern deep model". CellBender's network is not what holds it back; the per-library training loop, the knapsack output stage, the UMI-curve heuristics and the single run-level ambient profile are. A model that replaces those four parts and keeps a plain MLP wins on speed by construction, and it wins on accuracy only if it corrects the dominant ambient genes in dirty nuclei data without touching clean data, which is a claim that existing truth datasets can test on 10x and cannot yet test on Parse, Rhapsody or brain. The most durable contribution available to a lab that runs all three platforms on brain nuclei is therefore the missing ground truth as much as the model: a pooled-genotype or cross-species cortex nuclei preparation split across 10x, Parse and Rhapsody would decide every open question in this report, including whether split-pool and microwell backgrounds follow the unit structure proposed here.

Three inexpensive experiments should precede any pretraining. Profile CellBender v0.4.0 on three to five representative libraries on each GPU type, to replace the T4-era baseline with a real one. Run CellSweep and AmbiDose against CellBender on the strain-mixed kidney data and one Parse species mixture, to learn whether a non-neural tool already clears the bar. And fit the proposed mixture model per library with no pretraining, which needs no training corpus and already delivers the 10x speed target if the throughput estimates hold. If the per-library prototype matches CellBender on the two-dimensional endpoint, amortization becomes an engineering step with a known payoff; if CellSweep matches both, the case for a neural model rests on calibration and label-free operation and should be argued on those grounds alone.
